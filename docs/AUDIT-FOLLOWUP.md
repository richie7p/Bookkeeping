# PDF audit follow-up — Bookkeeping

Scope: portfolio technical audit, pages 5–6; revision work on 2026-10-04.

| Finding | Change and evidence |
| --- | --- |
| Windows official build failed with ENOENT | Vite is resolved from the installed package and launched with Node. No shell-dependent `.bin` spawning. Wrapper tests include a real Vite process and Windows directory junctions. |
| Dependency and type/lint failures | Lockfile refreshed, vulnerable transitive dependencies updated, safe error rendering and empty-catch lint fixed. CI checks the full dependency tree. |
| Missing ledger tests | Domain tests cover income/expense, liabilities, net-worth-preserving transfers, orphan transfers, invalid/overflow amount input and validated backup round trips. Additional boundaries cover exact 5 MB UTF-8 payloads, oversized legacy data, future storage envelopes, quota/read failures and safe aggregate arithmetic. |
| No backup / fragile browser persistence | Downloadable JSON backup; bounded and schema-validated import with replacement confirmation; quota warning; corrupt/unsupported-version saved data is preserved and automatic writes paused until an explicit valid restore. Export, import and every ledger mutation share the same 5 MB check; rejected edits keep their input open and leave the ledger untouched. An explicit raw download preserves every byte of an oversized or unsupported old save for manual recovery, without labelling it a directly importable backup. |
| Generated repository noise | Compiled `.vercel/output` and preview runtime logs/status are untracked and ignored. Referenced authoring skills and source assets remain. |
| Browser interactions insufficiently checked | Desktop/mobile tests create a transaction, reload it, export/import with confirmation, reject corrupt backups and report quota errors. They also download unknown-version saves byte-for-byte, restore explicitly, reject unsafe monetary totals, and reject an edit beyond a near-5 MB ledger without closing the input or damaging its restorable backup. Controls stay inert until client hydration to avoid lost early clicks. |

Reproduce with Node 22: `npm ci`, `npm run lint`, `npm run typecheck`, `npm test`, `npm audit --audit-level=low`, `npm run build`, `npx playwright install chromium`, `npm run test:e2e`. `E2E_DEV=1` runs the same interactions against the development server; default tests use the production preview. CI also validates Windows and Ubuntu clean installs/builds.

The app stores whole TWD amounts, rounded on entry, with a per-entry bound of NT$1 trillion. BigInt intermediate arithmetic avoids precision loss when values cancel. Import and mutations additionally bound the sum of absolute opening balances plus all transaction amounts to `Number.MAX_SAFE_INTEGER`, so any balance, net worth, category or monthly subtotal remains exact. This conservative limit can reject enormous cancelling ledgers as well as overflowing ones; values are never silently rounded or clamped. Balances use all transactions; monthly summaries filter by date.

Standard backups are compact version-1 JSON, at most 5 MiB (5 × 1024 × 1024 UTF-8 bytes), including the envelope. Export never emits a standard backup that the same importer rejects for size. Browser storage can fill before that limit; the visible quota warning means current data is in memory and should be exported immediately. Oversized, corrupt, unsafe-total or unknown-version historical saves remain untouched and writes are blocked; the recovery download contains their exact original storage string. Such raw files require manual repair/splitting and are not silently truncated, automatically converted, or advertised as importable standard backups. Backups and recovery files contain financial data in plaintext and should be kept privately. No cross-device account service or encryption is added.

Validation counts: 221 scaffold/shared tests, 15 product domain tests, and 14 browser tests per mode (7 scenarios × desktop/mobile), run against both the production build and development server. Latest-head Windows/Ubuntu results are in the draft PR checks. The additional three boundary failures were independently reproduced before the fixes and reviewed by a second agent after implementation.

The required Grok preview extension still emits `ERR_BLOCKED_BY_RESPONSE.NotSameOrigin` on an ordinary local preview host. First-party ledger interactions are tested separately and the platform integration is preserved. The actual deployed domain and platform response headers have not been changed or verified here. Financial/accounting certification is outside these software tests.
